# Как устроен ReelsMaker

Документ для тех, кто хочет понять, что происходит внутри, поправить код или написать монтажный лист руками.
Как пользоваться — в [README](../README.md).

## Путь от видео до роликов

```
папка сюжета ─► ffprobe ─► расшифровка ─► реплики ─► монтажный лист ─► схемы вариантов ─► ffmpeg ─► ролики
 (видео, роли)  (длина,    (faster-      (r01,      (edit.json,        (VariantPlan:      (NVENC/   (mp4, обложка,
                 поворот)   whisper)      r02…)      пишет агент)       сцены, кроп,       x264)     контактный лист)
                                                                         вставки, текст)
```

1. **Сюжет** — папка в папке входа. `apps/pc-agent/src/montage.ts` (`scanMontage`) перечисляет видео, читает
   `story.json` (роли, кроп, число вариантов), расшифровку основы и `edit.json`.
2. **ffprobe** (`probe.ts`) даёт длительность, наличие звука и размер кадра **как он выглядит на экране**: видео с
   телефона записано 1920×1080 с поворотом −90°, ReelsMaker показывает его как 1080×1920.
3. **Расшифровка** (`stt.ts` → `py/transcribe.py`): отдельный процесс Python с faster-whisper, по строке JSON на файл,
   слова с временем начала и конца. Результат — `<видео>.transcript.json` рядом с видео; устаревает, если видео новее.
4. **Реплики** (`workers/render/src/montage.ts`, `splitReplicas`): слова режутся по концу предложения или паузе
   ≥ 0,55 с; к каждой реплике — небольшой запас до и после, но не дальше середины паузы, чтобы соседние не наезжали.
5. **Монтажный лист** `edit.json` — что собирать (формат ниже). Его пишет агент или вы.
6. **Схемы вариантов** (`editToPlans`): лист проверяется и превращается в `VariantPlan` для каждого варианта. Ошибки
   называют вариант и сегмент («вариант v2, сегмент 3: нет реплики r99»), предупреждения — про почти-дубли,
   выход рамки экрана за охранную зону, лишние поля.
7. **ffmpeg** (`workers/render/src/ffmpeg/graph.ts`): граф фильтров собирается из схемы, рендер — `render.ts`, затем
   обложка и контактный лист 3×2 (`preview.ts`).

## Исходники и роли

| Роль | Что | По имени файла |
|---|---|---|
| `talk` — основа | крупный план; источник звука и субтитров, пока нет озвучки | голова, крупный, основа, говор, talk, close, a-roll |
| `wide` — дальний | перебивки: картинка меняется, звук остаётся с основы | дальний, общий, перебив, wide, b-roll |
| `screen` — скринкаст | вставка экрана в рамку; их может быть несколько | экран, скрин, интерфейс, screen, record |
| `voice` — озвучка | отдельные аудиофайлы: **звук и субтитры идут с них**, видео даёт только картинку; дублей может быть несколько | любой аудиофайл (wav, mp3, m4a…) |

Роли, заданные в интерфейсе, пишутся в `story.json` и важнее имён:

```json
{
  "sources": { "talk": "IMG_0824.MOV", "wide": "IMG_0815.MOV", "screen": ["экран — панель.mp4", "экран — гитхаб.mp4"] },
  "crops": { "IMG_0824.MOV": { "x": 0.1, "y": 0.05, "w": 0.8, "h": 0.8 } },
  "count": 5
}
```

`crops` — кроп в долях кадра (0…1) с учётом поворота, поэтому годится и для превью, и для сборки. `count` — сколько
вариантов нужно; агент берёт число отсюда, проверка листа предупреждает, если вариантов больше или меньше.

Остальные ключи озвучки: `sources.voice` — одно имя или массив (порядок задаёт владелец; `""` — отказ от озвучки,
аудиофайлы по расширению не подбираются), `voiceLetters` — буква каждой озвучки (`a`, `b`…), закреплена за файлом
навсегда: удаление и перестановка не сдвигают id реплик в листе, буква удалённой не выдаётся заново; `voiceMic` —
метка микрофона записи (ключ сохранённого образца шума); `voiceClean: false` — без очистки; `muteVideo: true` —
звук видео не нужен.

## Монтажный лист `edit.json`

```jsonc
{
  "version": 1,
  "notes": "о чём сюжет, в двух фразах",
  "layout": {
    "wideScreenBox":  { "x": 35, "y": 220, "w": 1010, "h": 620 },  // рамка экрана на дальнем, пиксели кадра 1080×1920
    "closeScreenBox": { "x": 35, "y": 220, "w": 1010, "h": 560 },  // на крупном (нет — как у дальнего)
    "wideOffset": 0, "screenOffset": 0                              // сдвиг дальнего/экрана от основы, если сняты синхронно
  },
  "variants": [
    {
      "id": "v1",
      "hook": "Я был мясным прокси между агентами",   // заголовок первых 2–3 с; нет — из первой реплики
      "segments": [
        { "replica": "r26" },                              // крупный план
        { "replica": "r27", "view": "wide" },              // перебивка: картинка с дальнего с той же секунды
        { "replica": "r28", "view": "wide", "wideAt": 40 }, // …или с 40-й секунды дальнего
        { "replica": "r30", "screen": 12.5, "screenFile": "экран — панель" }, // крупный + экран с 12,5 с этого скринкаста
        { "replica": "r31", "view": "wide", "screen": true }, // дальний + экран с той же секунды, что звук
        { "replica": "r32", "cutStart": 0.4, "cutEnd": 1.2 }, // подрезать реплику
        { "start": 481.4, "end": 489.9 }                   // произвольный отрезок основы (время слов — команда rm words)
      ],
      "blocks": [ { "segment": 3, "text": "Шаг 1", "offset": 0.3, "duration": 2 } ],  // плашки, по желанию
      "captions": true
    }
  ]
}
```

Без озвучки звук и субтитры у каждого сегмента — с основы, на отрезке реплики. С озвучкой (см. «Озвучка и очистка»)
сегмент задаётся репликой озвучки: `{ "voice": "b03" }` (файл определяет буква реплики), либо отрезком `start`/`end`
в секундах озвучки (озвучек несколько — `"voiceFile": "озвучка 2"`); крупный план показывает основу с той же секунды,
что звук, или с секунды `at` (сдвиг для всего листа — `layout.talkOffset`). Поле `note` — подпись сцены для
владельца, на сборку не влияет. Звук и субтитры — только с озвучки, основа без звука или `muteVideo` без озвучки дают
ролик без звука и субтитров (сегменты тогда только `start`/`end` в секундах видео).

Проверка листа предупреждает, если кадр держится меньше 2,5 с: «кадр» — подряд идущие сцены с одной картинкой без
скачка (скринкаст продолжается с того же места, фон идёт дальше), вырезанная пауза в звуке кадр не рвёт.

Без озвучки звук и субтитры у каждого сегмента — с основы, на отрезке реплики. `view` и `screen` меняют только картинку:
если перебивка короче отрезка звука, последний кадр держится до конца сегмента. Рамку экрана, вышедшую за охранную зону,
сборщик сдвигает внутрь и предупреждает.

## Схема варианта и граф ffmpeg

`VariantPlan` (`workers/render/src/types.ts`) — то, что реально собирается: сцены с отрезком основы (`trim`), кропом,
картинкой перебивки (`picture`), вставкой (`inset` с рамкой и кропом), хук, плашки. Оформление одно на все варианты:
темп и голос как сняты, без зума и цветокора.

На каждую сцену граф открывает свои входы: основа (звук и картинка), дальний — если перебивка, скринкаст — если вставка.
Цепочка картинки сцены:

```
trim → fps → crop (кроп исходника) → scale (заполнить 1080×1920) → crop 1080×1920 → [tpad, если перебивка короче]
       скринкаст: trim → crop → scale (вписать в рамку целиком) → overlay по центру рамки
```

Сцены склеиваются `concat`, затем поверх — один ASS-файл с хуком, плашками и субтитрами (`libass`, шрифты кладутся
рядом в рабочую папку), `yuv420p`. Кодирование — `h264_nvenc` (CQ 23) или `libx264` (CRF 21), AAC 160k, `+faststart`.
Два варианта собираются параллельно (NVENC), каждый — в свою папку `vNN/` с `plan.json` и `ffmpeg.log`.

## Субтитры и охранная зона

`workers/render/src/ass.ts`:

- слова переносятся на шкалу ролика (обрезка сцен, склейки); обрывок слова на краю отрезка (хвост прошлой фразы)
  в субтитры не попадает;
- слова собираются в куски: не больше `maxWords` слов и **не длиннее `maxChars` символов** — кусок всегда одной строкой;
  новый кусок — после конца предложения, паузы > 0,7 с или на склейке сцен;
- кусок не заходит на время следующего: два субтитра сразу libass ставит стопкой, и второй уехал бы вверх.

Охранная зона Reels для кадра 1080×1920 — сверху 220, снизу 450, по бокам 35 px (`SAFE_AREA` в `types.ts`).
Хук прижат к её верху, субтитры — к низу (на крупном плане это грудь, а не лицо), плашки — над субтитрами.
Тест `presets.test.ts` проверяет, что текст встроенного пресета не выходит из зоны.

## Оформление и шрифты

Встроенный пресет — `workers/render/presets/default.json` (Home Video для хука, Montserrat для субтитров и плашек).
Окно «Оформление» в интерфейсе меняет шрифт, размер, цвет, цвет и толщину обводки трёх слоёв; выбор хранится в
`<RF_DATA_DIR>/style.json` поверх встроенного пресета (`apps/hub/src/style.ts`). Свои шрифты загружаются файлом
`.ttf`/`.otf` в `<RF_DATA_DIR>/fonts`; семейство, по которому libass ищет шрифт, читается из таблицы `name` самого файла
(`workers/render/src/fonts.ts`). Новые сборки сразу идут с новым оформлением, готовые — по кнопке «Пересобрать».

## Агент-монтажёр

`apps/hub/src/agent.ts` запускает Claude Code так же, как его запускает расширение VS Code, но без окна:

```
claude --output-format stream-json --input-format stream-json --verbose --include-partial-messages
       --permission-prompt-tool=stdio --permission-mode=acceptEdits --strict-mcp-config --mcp-config {"mcpServers":{}}
       --model <модель> --append-system-prompt <подсказка монтажёра> [--resume=<сессия>]
```

- **Подсказка** (`editor-prompt.ts`) объясняет роли, формат листа, охранную зону, команды `rm` и порядок работы:
  brief → кадры → лист → check → build → смотреть контактные листы → доклад.
- **Разрешения** (`autoDecide`): чтение — всегда; правка и запись — только внутри папки сюжета; Bash — только команда
  `rm` и безобидное чтение (`ls`, `cat`, `ffprobe`…) без конвейеров и перенаправлений. Остальное — вопрос в окне.
- **Сессия** сюжета — `<сюжет>/.rm/agent.json`, история окна — `.rm/chat.json`; после перезапуска сервера беседа
  продолжается (`--resume`).
- **Прокси**: если задан `RF_AGENT_PROXY` и он отвечает, агенту выставляются `HTTPS_PROXY`/`HTTP_PROXY`.

### Команда `rm` — API сюжета

`node apps/hub/cli/rm.mjs [--story <сюжет>] <команда>` (агенту сюжет и адрес сервера передаются переменными
`RM_STORY`, `RM_HUB`):

| Команда | Что |
|---|---|
| `brief` | исходники, роли, скринкасты, сколько вариантов нужно, реплики, текущий лист и его проверка |
| `replicas [с] [по]` | реплики в окне времени |
| `words <с> <по> [файл]` | слова источника звука (озвучки, без неё основы) со временем — резать внутри реплики; озвучек несколько — укажите файл |
| `frames <роль\|файл> <сек>…` | кадры jpg (с кропом) — агент смотрит их как картинки |
| `grid <роль\|файл> [N]` | N кадров равномерно по файлу |
| `roles talk=… wide=… screen=… [screen=…] [voice=…]` | назначить роли (`screen=` и `voice=` можно повторять; `voice=` без файла — снять озвучку) |
| `mute on\|off` | звук видео не нужен / нужен |
| `transcribe [--force]` | расшифровать источники звука: все озвучки, без них основу |
| `check` | проверить `edit.json` |
| `build [v1,v2] [--cpu] [--par N]` | собрать варианты, дождаться, напечатать пути к роликам и контактным листам |
| `runs` | прошлые сборки |

## Озвучка и очистка

**Источник звука.** Озвучки (`sources.voice`) → иначе основа (если звук видео не отключён и он есть) → иначе ролик без
звука (`anullsrc`, без субтитров). Сегмент озвучки собирается как «картинка из другого файла»: звук и субтитры берутся
с файла озвучки на отрезке, картинка — с основы (`picture`), дальнего плана или скринкаста; картинка короче реплики
держит последний кадр. Каждая озвучка режется на реплики отдельно (`splitReplicas` с буквой файла).

**Запись.** Страница пишет звук без сжатия (AudioWorklet, PCM 24 бит; запасной путь — MediaRecorder на максимальном
битрейте) и отправляет на `POST /api/stories/:id/voice`; сервер перекодирует в wav 48 кГц и кладёт в папку сюжета
новым файлом (имена удалённых не переиспользуются).

**Очистка** (`apps/pc-agent/src/voice-clean.ts`). «Чистая» копия — `<сюжет>/.rm/clean/<имя>.wav` с описанием
(`.json`: версия цепочки, режим, образец, размер и время оригинала — копия пересчитывается, если что-то изменилось).
Цепочка: `highpass` 80 Гц → узкие режекторы `bandreject` на кратных 1 кГц (`COMB_KHZ`) → `afftdn` по образцу шума
(`asendcmd` … `sn start/stop`) → срез задержки `afftdn` (1200 отсчётов) → `agate` с порогом от измеренного шума →
`loudnorm`. Образец — по убыванию надёжности: самый длинный тихий кусок в первых 3 с этой записи (щелчок от кнопки
записи не мешает); сохранённый образец того же микрофона (`<RF_DATA_DIR>/noise/`, клеится перед записью и срезается
после); иначе `afftdn` отслеживает шум сам (заметно слабее). Студийные добавки (эквалайзер, компрессор) не
включены: на USB-микрофоне они подтягивают остаточный шум. Расшифровка и реплики остаются по оригиналу — тайминг копии
совпадает с ним до отсчёта.

**Виртуальный микрофон** (`apps/mic-clean`). `buildLiveGraph` строит ту же цепочку для живого потока (без `loudnorm`
и `apad`, вместо них усиление и лимитер); `mic-clean.ts` — настройки и план запуска ffmpeg, `mic-clean-cli.ts` отдаёт его
Python-программе в трее `micclean.py`: она запускает ffmpeg (DirectShow-вход → PCM в stdout), держит буфер между ffmpeg
и звуковой картой (часы микрофона и кабеля расходятся: лишнее роняется, нехватка — тишина) и выводит звук в
`CABLE Input` через WASAPI. Режим «без обработки» — тот же поток без фильтров.

## Сервер и страница

`apps/hub/src/server.ts` — HTTP только на `127.0.0.1`, без внешних зависимостей; `page.ts` — одна страница со
встроенным JS. Долгие дела (расшифровка, сборка) идут через очередь задач (`jobs.ts`) по одной, с журналом и прогрессом.

Страница не перерисовывается вслепую: раз в 2 с она спрашивает **отпечаток сюжета** (`/api/stories/:id/stamp` —
имена, размеры и время файлов папки и прогонов) и обновляет вид, только если он изменился. Сборку, запущенную агентом,
она подхватывает сама; карточка ролика меняется, только когда меняется состояние её варианта, поэтому ничего не мигает.

Основные маршруты:

| Маршрут | Что |
|---|---|
| `GET /api/state` | папки, кодировщик, модели агента |
| `GET /api/stories`, `GET /api/stories/:id` | список сюжетов; сюжет с исходниками, репликами, листом, прогонами |
| `GET /api/stories/:id/stamp` | отпечаток сюжета и активные задачи |
| `POST /api/stories/:id/roles` · `/crop` · `/settings` | роли · кроп исходника · число вариантов, `muteVideo`, `voiceClean` |
| `POST /api/stories/:id/voice` · `/voice/delete` · `/voice/clean` | запись озвучки (тело — аудио) · убрать в корзину · пересчитать очистку; `GET /in/<сюжет>/…` — прослушать |
| `POST /api/stories/:id/frames` · `GET …/words` | кадры · слова основы |
| `POST /api/stories/:id/transcribe` · `/check` · `/build-edit` | расшифровка · проверка листа · сборка |
| `GET/POST /api/stories/:id/agent…` | окно агента: история, сообщение, разрешение, стоп, новая беседа |
| `GET/POST /api/style`, `POST /api/fonts` | оформление, загрузка шрифта |
| `/out/…`, `/fonts/…` | готовые ролики (с Range для перемотки), шрифты для образца |

## Сюжет из сценок

Кроме сюжета из исходников есть старый режим — папка коротких сценок `NN_<слово>.mp4` (`01_хук_…` — всегда первая,
`NN_финал` — последняя, `NNa`/`NNb` — дубли). Сборщик сам раскладывает сценки в N вариантов с разным порядком
(`workers/render/src/planner/rules.ts`). Режим определяется сам: если видео узнаются как основа, дальний или экран —
это сюжет из исходников.

## Тесты

`npm test` — около 150 тестов на `node:test`: разбор имён и ролей, реплики, проверка листа, граф ffmpeg (входы, кроп,
вставки, охранная зона), субтитры (куски, одна строка, без наездов), шрифты, HTTP-сервер с подменённым рендером,
протокол агента с подменённым Claude Code. `render.e2e.test.ts` собирает два ролика настоящим ffmpeg, если он есть (в том числе ролик с озвучкой); тесты очистки
проверяют на настоящем ffmpeg, что линии гребёнки вырезаются, длина и тайминг сохраняются. Буфер виртуального микрофона:
`python -m unittest apps/mic-clean/test_micclean.py`.
